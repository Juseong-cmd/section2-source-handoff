# SECTION2 근태관리 사내 재구현 가이드

이 문서는 사내 개발 에이전트에게 전달할 기능 명세입니다. SECTION2의 동작을 사내 인증·DB·배포 환경에서 재현하는 것을 목표로 합니다. 가상 팀원과 가상 일정으로 개발하고, 운영 데이터 이관은 회사의 승인된 절차에서 별도로 다룹니다.

## 1. 시작 범위와 구현 순서

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| 1 | 사내 로그인, 역할, 팀원, 달력, 근태 등록 | 여러 사람이 달력을 조회하고 자기 근태를 추가·수정할 수 있습니다. |
| 2 | 공통 일정, 잔업, Bay, 이력, CSV | 관리 작업과 동시 저장 시나리오를 가상 데이터로 통과합니다. |
| 3 | 라운지, 그림, 투표, 꾸미기 | 브라우저 채점, 그림 보관과 중복 없는 EXP 지급을 검증합니다. |
| 4 | 운영 | 백업 복원, 사내 도메인, 접속 로그 및 사용량 집계를 검증합니다. |

기존 앱은 Next.js App Router, React, TypeScript, CSS 변수, Postgres 계열 저장소를 사용합니다. 원본 소스를 사내에 가져올 수 있으면 승인된 저장소에 넣고 아래 상대 경로를 시작점으로 삼습니다. 소스 전송이 제한되면 사내 표준 스택으로 아래 동작과 인수 테스트를 구현합니다.

## 2. 화면과 동작

| 화면 | 재현할 동작 | 원본 위치 |
| --- | --- | --- |
| 달력 | 월간 격자, 팀원별 주간 현황, 이전·다음·오늘, 날짜 클릭 모달, 근태/잔업/통합 보기, CSV. 동시 일정은 가로 레인으로 정리 | `app/section2/page.tsx`, `app/attendance-lanes.ts` |
| 근태 | 연차·교육·유연근무·가족 관련·기타 항목, 기간·메모, 등록/수정/삭제 이력 | `app/data.ts`, `app/attendance-display.ts`, `app/store.ts` |
| 공통 일정 | 회의·식사, 제목·대상자·장소·메모, 날짜 범위 및 전일 선택. 팝업 날짜 헤더 드래그, Shift 범위, 월간 드래그로 같은 등록 흐름 진입. 저장·수정·취소 이력 보존 | `app/common-events/`, `app/api/common-events/` |
| 잔업·Bay | 잔업 직접/합의/랜덤 지정, 기간 등록 시 주말·공휴일 포함 여부. Bay는 Wet·Etch·Fusion 월 기본 배정, 이월, 기간 한정 지원 배정과 취소. 전일 부재와 겹치면 차단하고 부분 근무는 확인을 요구 | `app/section2/page.tsx`, `app/bay/`, `app/api/bay/` |
| 게시판·관리 | 피드백과 댓글, 팀원 활성화·표시색, 변경 이력. 사내 로그인 계정과 팀원 레코드를 연결 | `app/feedback/`, `app/admin/` |
| 라운지 | 캐릭터 EXP, 5레벨마다 보상, 소품 장착/해제. 오늘의 그림, 작품 확대, 보관함, 투표, 날짜별 수상작 | `app/lounge/` |

날짜는 한글 표시와 한국 시간 `Asia/Seoul`을 사용합니다. 날짜 자체는 `YYYY-MM-DD`, 사건 시각은 UTC 타임스탬프로 저장합니다. 기간 종료일은 포함합니다. 한국 공휴일은 [우주항공청 공식 월력요항](https://www.kasa.go.kr/bbs/BBSMSTR_000000000018/view.do?nttId=B000000003234Li6nD2)과 대조합니다. 2028년 데이터는 [한국천문연구원 잠정 자료](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2028)를 표시한 상태입니다. 패밀리데이는 별도 팀 규칙으로 구분합니다.

## 3. 데이터와 API

필수 엔터티는 팀원, 근태, 공통 일정 및 이력, 잔업 배정, Bay 배정과 이력, 게시글과 댓글입니다. 라운지 데이터는 캐릭터 프로필/일일 EXP, 현재 작품, 불변 작품 보관함, 날별 투표 및 수상 기록으로 분리합니다.

| 기존 경로 | 사내 구현에서 지킬 계약 |
| --- | --- |
| `GET /api/state?view=calendar` | 팀원·근태·일정에 필요한 상태와 변경 버전. 그림 이미지와 정산은 이 응답에서 제외 |
| `POST /api/state` | 변경한 레코드만 전달. 레코드 revision 및 request ID로 충돌·재전송 처리 |
| `GET/POST /api/common-events`, `GET/POST /api/bay` | 필요한 컬렉션만 조회. 생성·수정·취소 명령은 서버 검증 후 본문과 이력을 함께 저장 |
| `GET /api/drawing-history` | 내 작품/전체 작품, 최신순, 6개 단위. 조회는 저장을 일으키지 않음 |
| `GET/POST /api/drawing-votes` | 날짜별 집계, 변경 가능한 1표, 확정 결과와 EXP 지급 영수증 |
| `GET/POST /api/lounge-wardrobe` | 보유·장착 상태, 획득/장착 시 소유권과 최신 revision 검증 |
| 예약 백업·정산 | 사내의 인증된 작업으로 운영. 기존 기준은 매일 KST 17:30 백업과 00:05 투표 정산 |

예시 근태 레코드입니다. 모든 값은 가상입니다.

```json
{
  "id": "sample-absence-001",
  "memberId": "sample-member-01",
  "startDate": "2027-02-10",
  "endDate": "2027-02-12",
  "type": "annual",
  "label": "",
  "memo": "",
  "revision": 1
}
```

팀원 이름을 선택하는 기존 UX는 사내 인증과 별도로 취급합니다. 서버에서 로그인 계정과 팀원 권한을 확인하고 다른 사용자를 대신한 쓰기는 권한이 있을 때만 허용합니다. 공통 일정·Bay 쓰기는 예상 revision이 다르면 `409`와 최신 정보를 돌려줍니다. 같은 request ID로 재시도해도 중복 기록이나 중복 EXP가 없어야 합니다. 브라우저에 운영 DB 서비스 키를 전달하지 않습니다.

## 4. 라운지의 구체적인 규칙

- 그림 채점은 브라우저 Canvas와 Web Worker에서 합니다. 양방향 윤곽 거리, 완성도 45%, 정확도 35%, 형태 15%, 불필요한 선 억제 5%와 기존 게임 점수 보정을 사용합니다. 도트·빈 그림·무관한 선·정상 그림의 기준 사례를 마련합니다. 외부 AI 요청 경로는 만들지 않습니다.
- 하루에 한 작품을 제출하고, 제출 당시의 점수와 이미지를 날짜·팀원 키로 별도 보존합니다. 그림 보관함은 펼칠 때 조회합니다. 라운지 외 화면은 이력을 일괄 전송하지 않습니다.
- 투표는 KST 날짜 기준 활성 사용자 1인 1표이며 자정 전 변경할 수 있습니다. 자기 작품 투표는 막습니다. 득표 화면은 1표 이상인 공동 선두를 함께 강조합니다. 마감 후 최소 3표를 받은 공동 1위 모두에게 30 EXP를 한 번 지급합니다. 보상과 지급 기록은 같은 트랜잭션에서 갱신합니다.
- 꾸미기는 캐릭터별 착장과 사용자별 소유권을 분리합니다. 이동한 경우에도 장착 위치가 손·눈·귀 기준점에 맞는지 확인합니다.

## 5. 디자인과 점검

사내 허용 브랜드를 적용합니다. 토큰의 기준은 4px 간격, 기본 글자 14px, 모바일 조작 높이 44px입니다. 데스크톱과 모바일에서 날짜·이름·버튼이 같은 기준선에 놓이고, 그림·소품이 잘리지 않는지 확인합니다. 키보드 범위 선택과 감소된 모션 설정도 시험합니다.

- [ ] 2027년 2월 6~9일 달력 표기가 맞고, 주말·공휴일 제외 잔업에서는 모두 빠집니다.
- [ ] 2028년 10월 3일에 추석과 개천절을 함께 표시하고, 10월 5일을 대체공휴일로 표시합니다.
- [ ] 2~4일 범위 드래그, 전일 등록, 수정 이력, 비동시 변경 병합과 동일 항목 `409`를 확인합니다.
- [ ] Bay 월 이월, 부분 근무 확인, 전일 부재 차단, 동시 재시도 중복 방지가 동작합니다.
- [ ] 그림 채점·보존·투표 2표/3표·공동 1위·정산 도중 재시도를 검증합니다.
- [ ] 숨은 탭은 주기 조회를 멈추고, 같은 브라우저의 여러 탭이 접속 신호를 중복 전송하지 않습니다. 공통 일정·Bay의 조회는 전체 상태를 읽지 않습니다.
- [ ] 가상 데이터로 백업 복원을 수행하고, 320px·390px·1440px에서 주요 동작을 확인합니다.

원본 저장소 접근이 허용된다면 `app/calendar-holidays.test.ts`, `scripts/test-bay-integration.mjs`, `scripts/test-drawing-catalog.mjs`, `scripts/test-presence-tabs.mjs`의 테스트를 이관 초기에 실행합니다. 빌드에 제공하는 환경 파일은 사내 비밀 저장소를 사용합니다. 운영 Supabase 키, Vercel 설정, 채팅 토큰, 운영 화면의 개인·업무 데이터는 사내 개발 에이전트에게 전달할 명세에 넣지 않습니다.
